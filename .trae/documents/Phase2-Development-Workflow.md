## 三、测试配置规范（新增）

### 3.1 测试框架配置顺序

```
Phase开始时：
  步骤1：安装后端测试依赖
          pip install pytest pytest-cov httpx

  步骤2：创建pytest配置
          创建 tests/backend/test_*.py
          创建 pytest.ini

  步骤3：安装前端测试依赖
          npm install vitest @testing-library/react jsdom

  步骤4：创建vitest配置
          创建 tests/frontend/**/*.test.ts
          创建 vitest.config.ts

  步骤5：验证测试运行
          pytest tests/backend -v
          npx vitest run tests/frontend

  步骤6：验证覆盖率
          pytest --cov=app --cov-report=term-missing
          npx vitest run --coverage
```

### 3.2 覆盖率要求

| 类型 | 关键功能要求 | 普通功能要求 |
|------|-------------|-------------|
| 后端 | 100% | 80% |
| 前端 | 100% | 70% |

**关键功能清单（必须100%覆盖）**：
- AI结论生成逻辑
- 风险偏好系数计算
- 评分到结论映射
- 股票搜索逻辑
- 数据缓存逻辑

### 3.3 AC-4.3专项测试要求

**必须包含的测试用例**：

| 用例ID | 测试场景 | 验证点 |
|--------|----------|--------|
| TC-AC43-001 | 激进型(80/15/5) | 系数≈1.38, 结论等级最高 |
| TC-AC43-002 | 中性型(40/35/25) | 系数≈1.08, 结论等级居中 |
| TC-AC43-003 | 保守型(10/30/60) | 系数≈0.75, 结论等级最低 |
| TC-AC43-004 | 极端激进(100/0/0) | 系数=1.4, 边界验证 |
| TC-AC43-005 | 极端保守(0/0/100) | 系数=0.7, 边界验证 |
| TC-AC43-006 | None参数 | 系数=1.0, 默认行为 |

**通过标准**：同一基础评分下，激进型结论等级 >= 中性型 >= 保守型

## 四、代码评审强化清单

### 4.1 新增检查项E：测试完整性

| 检查ID | 检查内容 | 对照文档 | 通过标准 |
|--------|----------|----------|----------|
| **E-001** | **单元测试存在** | 测试文件 | 关键功能必须有单元测试 |
| **E-002** | **测试覆盖率达标** | pytest/vitest报告 | 关键功能100%覆盖 |
| **E-003** | **AC-4.3有单元测试** | 测试文件 | 6个专项用例存在 |
| **E-004** | **测试可通过** | pytest/vitest | pytest + vitest 全部通过 |
| **E-005** | **无测试破坏** | CI/CD日志 | 测试未因代码变更失败 |

### 4.2 更新后的检查项C：代码质量

| 检查ID | 检查内容 | 检查方法 | 通过标准 |
|--------|----------|----------|----------|
| C-001 | 命名规范 | 人工检查 | 变量/函数命名有意义 |
| C-002 | 无重复代码 | 人工检查 | DRY原则 |
| C-003 | 错误处理 | 人工检查 | try-catch存在 |
| C-004 | 类型安全 | TypeScript检查 | 无any滥用 |
| C-005 | 资源释放 | 人工检查 | 无内存泄漏 |
| **C-006** | **参数实际使用** | **代码检查** | **接收的参数必须使用** |
| **C-007** | **边界条件处理** | **代码检查** | **0值/None值/极端值处理** |

### 4.3 评审流程更新

```
步骤1: 准备阶段
├── 读取 PRD.md 验收标准
├── 读取 Technical-Architecture.md
├── 读取 Test-Plan.md
└── 确认测试框架已配置

步骤2: 代码检查
├── 检查项A：功能完整性（9项）
├── 检查项B：技术方案符合性（7项）
├── 检查项C：代码质量（7项，含C-006/C-007）
├── 检查项D：安全合规（4项）
└── 检查项E：测试完整性（5项）  ← 新增

步骤3: AC-4.3专项验证
├── 检查单元测试存在（6个用例）
├── 检查覆盖率报告
├── 运行单元测试验证
└── 运行API测试验证

步骤4: 评审结论
├── 所有检查项通过 → 批准合并
├── 任一检查项失败 → 拒绝合并
└── 输出：《评审结论书》
```

## 六、违规处理（强化版）

### 6.1 代码评审违规

| 违规情况 | 处理措施 |
|----------|----------|
| 未配置测试框架 | 评审不通过，阻塞 |
| E-001~E-005未检查 | 评审无效，重新评审 |
| C-006参数未使用 | 评审失败，必须修复 |
| C-007边界未处理 | 评审失败，必须修复 |
| AC-4.3单元测试缺失 | 评审失败，必须补充 |

### 6.2 测试违规

| 违规情况 | 处理措施 |
|----------|----------|
| 覆盖率不达标 | 测试失败，必须提高 |
| AC-4.3单元测试失败 | 测试失败，必须修复 |
| 测试破坏现有用例 | 提交被拒绝 |
