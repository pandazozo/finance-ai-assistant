| **阶段2：代码评审** | 无阻塞性问题，代码规范 | 返回修复后重新评审 |

| **阶段6：线上部署** | CI/CD完成，生产环境可用 | 检查部署配置 |
| **阶段7：线上测试** | 核心功能验证通过 | 返回修复，重新部署 |

## 🎯 UI/UX规范约束（必须遵守）

### 前端页面布局模板

**所有页面必须使用统一布局结构，违反将被Code Review拒绝**：

```tsx
// ✅ 正确的页面布局模板
export default function PageName() {
  return (
    <div className="flex flex-col h-full bg-bg-dark safe-area-inset">
      {/* 1. 顶部固定区域 - 使用 flex-none */}
      <div className="flex-none p-4 border-b border-border">
        {/* Header内容 */}
      </div>

      {/* 2. 可滚动内容区域 - 使用 flex-1 + overflow-y-auto + pb-20 */}
      <div className="flex-1 overflow-y-auto pb-20">
        {/* 内容 */}
      </div>

      {/* 3. 底部TabBar固定在屏幕底部（在外层App.tsx控制） */}
    </div>
  );
}
```

### 禁止的模式（违反将被打回）

```tsx
// ❌ 错误1：缺少safe-area-inset
<div className="h-full">

// ❌ 错误2：内容区域没有overflow-y-auto
<div className="flex-1">

// ❌ 错误3：内容区域没有pb-20导致被TabBar遮挡
<div className="flex-1 overflow-y-auto">

// ❌ 错误4：使用overflow-hidden阻止滚动
<div className="flex-1 overflow-hidden">

// ❌ 错误5：嵌套的flex容器没有正确设置
<div className="flex flex-col">
  <div className="overflow-auto"> {/* 应该用overflow-y-auto */}
</div>
```

### 组件开发规范

| 规范 | 说明 | 违反惩罚 |
|------|------|----------|
| **布局模板** | 所有页面必须使用统一布局模板 | Code Review拒绝 |
| **滚动测试** | 开发时必须手动测试滚动功能 | Code Review拒绝 |
| **安全区域** | 必须添加safe-area-inset | Code Review拒绝 |
| **底部间距** | 可滚动区域必须pb-20 | Code Review拒绝 |

## 🎯 方案评审对齐机制

### 对齐原则

1. **前置调研优先**：技术框架输出前，必须先做数据源、技术栈等前置调研
2. **用户体验导向**：不以技术细节提问，而以用户体验/产品价值提问
3. **利弊透明化**：涉及方案取舍时，必须提供充分利弊分析和理由
4. **框架确认后细化**：用户确认框架决策后，再细化技术方案

### 评审检查清单（架构师输出前）

- [ ] 数据源是否充分调研？（包含竞品对比、可行性分析）
- [ ] 技术方案能否实现产品需求？（功能完整性）
- [ ] 用户体验指标是否可达？（性能、稳定性）
- [ ] 扩展性路径是否清晰？（Phase 2/3演进）
- [ ] 方案取舍是否有充分利弊分析？（决策透明）

### 用户确认标准问题

| 问题类型 | 问题 | 回答选项 |
|----------|------|----------|
| 产品价值 | 换手机数据丢失是否可接受？ | 可接受 / 不可接受 |
| 技术取舍 | MVP阶段用规则引擎是否可接受？ | 可接受 / 不可接受 |
| 性能指标 | 行情数据3-5秒延迟是否可接受？ | 可接受 / 不可接受 |

#### 输出
- [PRD文档](file:///workspace/.trae/documents/PRD.md)（产品需求文档）

- [ ] 已定义验收标准
- [ ] 已考虑用户体验（UX）
- [ ] 功能优先级明确（P0/P1/P2）

## 📋 完整研发流程

### 1. 需求阶段
```
用户需求 → 产品经理 → 输出PRD → 方案评审 → 确认需求

```

## 🔄 流程优化建议（基于实践经验）

| 优化点 | 优化前 | 优化后 | 理由 |
|--------|--------|--------|------|
| 测试时机 | 开发完再测试 | 边开发边自测 | 尽早发现问题 |
| 依赖版本 | 固定版本号 | 灵活版本范围 | 避免兼容性问题 |
| API兼容性 | 需要完全重构 | 渐进式兼容 | 减少重构风险 |
| 环境配置 | 手动配置 | 环境变量管理 | 提高可移植性 |
| 提交粒度 | 大批量提交 | 小批量多次提交 | 便于回溯和定位问题 |
| UI规范 | 无约束 | 统一模板+Code Review检查 | 避免滚动等基础问题 |

### BUG-004：详情面板滚动问题
- **发现日期**：2026-05-12
- **严重程度**：P1
- **问题描述**：从底部升起的详情面板无法滚动
- **根本原因**：
  1. 滚动容器使用了`max-h-[calc(85vh-180px)]`但没有正确的iOS Safari优化
  2. 缺少`WebkitOverflowScrolling: 'touch'`导致iOS上滚动不流畅
- **修复方案**：
  ```tsx
  <div 
    className="overflow-y-auto" 
    style={{ 
      maxHeight: 'calc(85vh - 160px)',
      WebkitOverflowScrolling: 'touch',
      overscrollBehavior: 'contain'
    }}
  >
  ```
- **约束改进**：
  1. 所有底部升起面板必须添加iOS滚动优化
  2. QA测试必须包含底部面板滚动测试
