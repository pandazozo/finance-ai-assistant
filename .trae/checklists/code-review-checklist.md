# 代码评审 - 检查清单

## 代码质量
- [ ] 代码符合项目编码规范
- [ ] 命名有意义且一致
- [ ] 函数/方法长度适中
- [ ] 避免重复代码（DRY原则）
- [ ] 适当的注释（仅解释为什么而非怎么做）
- [ ] 文件组织合理

## 功能正确性
- [ ] 代码实现满足需求
- [ ] 逻辑正确，无明显bug
- [ ] 边界条件处理正确
- [ ] 错误/异常处理完善
- [ ] 资源正确释放（连接、文件等）

## 性能
- [ ] 避免N+1查询
- [ ] 适当的缓存使用
- [ ] 避免不必要的计算
- [ ] 大数据量场景考虑

## 安全
- [ ] 输入验证与清理
- [ ] 防止SQL注入
- [ ] 防止XSS攻击
- [ ] 敏感信息未硬编码
- [ ] 认证授权正确实现
- [ ] CORS配置正确

## 可测试性
- [ ] 代码结构便于测试
- [ ] 有对应的单元测试
- [ ] 测试覆盖核心逻辑

## 可维护性
- [ ] 代码结构清晰
- [ ] 依赖关系合理
- [ ] 变更影响范围小
- [ ] 代码自解释性好

## Git提交
- [ ] 提交信息清晰有意义
- [ ] 一次提交只做一件事
- [ ] 不提交调试代码/注释掉的代码
- [ ] 不提交敏感信息
